# Redesign

Audit before changing. A redesign should improve hierarchy, identity, and
usability without accidentally deleting learned behavior or working flows.

## 1. Inventory

- existing brand assets, tokens, typography, imagery, and component library
- navigation and information architecture
- primary user journeys and business-critical actions
- responsive breakpoints and interaction states
- accessibility failures and obvious visual inconsistencies

Capture before screenshots at 320, 768, 1024, and 1440px.

## 2. Decide preservation level

- **Preserve** — keep the visual language; repair hierarchy, spacing, states,
  responsiveness, and consistency.
- **Evolve** — retain recognizable brand signals while introducing a clearer
  system and stronger signature.
- **Overhaul** — replace the language because it conflicts with the product or
  audience; preserve workflows and validated content.

State what remains, what changes, and why before editing.

## 3. Fix in leverage order

1. information hierarchy and navigation
2. typography and color system
3. layout, spacing, and density
4. component/state consistency
5. responsive and accessibility failures
6. motion and finishing details

Use realistic content. Placeholder copy and uniformly short data hide wrapping,
density, and overflow defects.

## 4. Verify

Re-run the primary journeys, compare before/after screenshots, and invoke
`ui-reviewer`. A prettier screen that breaks task completion is a failed
redesign.
