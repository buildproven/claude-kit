# Product UI

Design repeated-use interfaces as precision instruments. Function and
information hierarchy outrank spectacle.

## Direction

- Ground every screen with navigation, location, workspace/user context, and
  the next useful action.
- Let the task decide density. A trading or operations surface can be compact;
  a focused approval flow can breathe.
- Reserve color for action, status, error, success, and identity. Gray carries
  structure.
- Use expressive display typography sparingly; controls and dense data need
  highly readable type.
- Motion communicates state change. Prefer 150–250ms transitions; avoid
  decorative choreography in daily-use tools.

## Structure

- Design tables, lists, metrics, settings, and workflows for their information,
  not as identical cards.
- Choose one depth strategy: subtle borders, surface shifts, or restrained
  shadows. Do not mix all three arbitrarily.
- Use semantic tokens and a consistent spacing/radius scale.
- Include loading, empty, error, disabled, hover, active, focus, success, and
  recovery states.
- Keep critical actions keyboard accessible and test narrow/mobile layouts,
  even when desktop is primary.

## Anti-generic check

- Could this dashboard belong to any SaaS product?
- Does every metric have the same icon-left/number-large/label-small pattern?
- Is the sidebar, card grid, and spacing identical to a starter template?
- Is color decorative rather than meaningful?
- Is navigation missing because only a component, not a real product screen,
  was designed?

Replace generic structure with something derived from the user's actual job,
domain vocabulary, and decision sequence.
